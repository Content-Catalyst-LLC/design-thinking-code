# Validation Protocol

Use this checklist before interpreting model outputs.

## Data validation

- [ ] Every candidate frame has a clear name.
- [ ] No duplicate frames exist.
- [ ] All required criteria are present.
- [ ] All required scores are numeric.
- [ ] Scores are in the expected range.
- [ ] Scenario weights sum to 1.0.
- [ ] Risk components are documented.
- [ ] Evidence quality is documented.
- [ ] Frame confidence is documented.
- [ ] Counterframes are documented.

## Research validation

- [ ] Frames are tied to stakeholder evidence.
- [ ] Evidence includes more than one stakeholder perspective.
- [ ] Excluded or underrepresented groups are documented.
- [ ] Systems constraints are documented.
- [ ] Frame risks are decomposed rather than treated as vague concerns.
- [ ] Narrowness risk, stakeholder exclusion risk, causality risk, and political distortion risk are reviewed separately.
- [ ] Assumptions are explicit.
- [ ] Disagreements are recorded.
- [ ] Counterframes are tested.
- [ ] Prototype implications are documented.

## Interpretation validation

- [ ] Rankings are compared across scenarios.
- [ ] Monte Carlo stability is reviewed.
- [ ] Weight sensitivity is reviewed.
- [ ] High-uncertainty frames are not overinterpreted.
- [ ] High-risk frames are not selected solely because they are actionable.
- [ ] Counterframe test priorities are reviewed.
- [ ] The next research or prototype step is clearly defined.
