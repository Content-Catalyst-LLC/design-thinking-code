# Model Card: Human-Centered Design Decision-Support Model

## Model name

Human-Centered Design Option Value Model

## Intended use

The model supports transparent comparison of human-centered design options during research synthesis, strategy review, prototype prioritization, administrative-burden analysis, and early implementation planning.

## Not intended for

- Automated decision-making.
- Replacement of stakeholder research.
- Replacement of domain expertise.
- Final approval of public policy, clinical, educational, financial, or safety-critical interventions.
- Ranking people or communities.
- Claiming that a design is equitable without direct evidence from affected stakeholders.

## Inputs

- Design option name.
- Human benefit score.
- Usability score.
- Stakeholder fit score.
- Burden score.
- Optional burden components.
- Optional evidence quality.
- Optional stakeholder confidence.
- Optional implementation complexity.
- Optional stakeholder visibility and exclusion-risk diagnostics.

## Outputs

- Weighted human-centered value.
- Burden index.
- Confidence-adjusted value.
- Rank within scenario.
- Monte Carlo rank stability.
- Bootstrap stability.
- Weight sensitivity summary.
- Stakeholder exclusion-risk diagnostic.

## Assumptions

The model assumes that option scores are provisional and that weights represent explicit institutional priorities. It also assumes that uncertainty and stakeholder invisibility should be modeled rather than hidden.

## Limitations

The model cannot determine whether a design option is morally legitimate, politically acceptable, historically informed, equitable, or contextually appropriate. Those judgments require human deliberation, stakeholder participation, fieldwork, domain expertise, and ethical review.

## Responsible use

Use this model as a documentation and deliberation tool. Treat disagreement about scores or weights as useful evidence that the design team needs further inquiry.
