# Validation Protocol

Use this checklist before interpreting model outputs.

## Data validation

- [ ] Every option has a clear name.
- [ ] No duplicate options exist.
- [ ] All required criteria are present.
- [ ] All required scores are numeric.
- [ ] Scores are in the expected range.
- [ ] Scenario weights sum to 1.0.
- [ ] Burden components are documented.
- [ ] Evidence quality is documented.
- [ ] Stakeholder confidence is documented.
- [ ] Stakeholder visibility and access-risk scores are documented.

## Research validation

- [ ] Scores are tied to stakeholder evidence.
- [ ] Evidence includes more than one stakeholder perspective.
- [ ] Excluded or underrepresented groups are documented.
- [ ] Administrative burden is decomposed rather than treated as a vague concern.
- [ ] Learning cost, compliance cost, psychological cost, and access cost are reviewed separately.
- [ ] Assumptions are explicit.
- [ ] Disagreements are recorded.
- [ ] Risks are categorized, not collapsed into one vague concern.
- [ ] Implementation constraints are documented.

## Interpretation validation

- [ ] Rankings are compared across scenarios.
- [ ] Monte Carlo stability is reviewed.
- [ ] Weight sensitivity is reviewed.
- [ ] High-uncertainty options are not overinterpreted.
- [ ] High-burden options are not selected solely because they score well.
- [ ] Stakeholder exclusion-risk results are reviewed.
- [ ] The next prototype or research step is clearly defined.
