# Validation Protocol

Use this checklist before interpreting model outputs.

## Data validation

- [ ] Every candidate insight has a clear name.
- [ ] No duplicate candidate insights exist.
- [ ] All required criteria are present.
- [ ] All required scores are numeric.
- [ ] Scores are in the expected range.
- [ ] Scenario weights sum to 1.0.
- [ ] Risk components are documented.
- [ ] Evidence quality is documented.
- [ ] Stakeholder diversity is documented.
- [ ] Prototype testability is documented.
- [ ] Evidence-source diagnostics are documented.

## Research validation

- [ ] Candidate insights are traceable to observations.
- [ ] Evidence sources are tagged.
- [ ] Stakeholder groups are documented.
- [ ] Research methods are documented.
- [ ] Contradictory cases are documented.
- [ ] Alternative explanations are reviewed.
- [ ] Solution-capture risk is reviewed.
- [ ] Interpretation limits are documented.
- [ ] Validation pathways are defined.
- [ ] Prototype-test implications are documented.

## Interpretation validation

- [ ] Rankings are compared across scenarios.
- [ ] Monte Carlo stability is reviewed.
- [ ] Weight sensitivity is reviewed.
- [ ] High-uncertainty insights are not overinterpreted.
- [ ] High-risk insights are not used as final design direction without validation.
- [ ] Evidence validation priorities are reviewed before ideation or prototyping.
- [ ] The next research, synthesis, or prototype step is clearly defined.
