# Validation Protocol

## Data validation

- [ ] Every concept has a unique name.
- [ ] Prototype type and fidelity level are documented.
- [ ] Desirability, feasibility, viability, responsibility, friction, and residual risk are scored.
- [ ] Evidence quality is documented.
- [ ] Stakeholder coverage is documented.
- [ ] Method triangulation is documented.
- [ ] Scenario weights sum to 1.0.
- [ ] Testing rounds are traceable.
- [ ] Decision thresholds are defined before interpretation.
- [ ] Risk-register entries have owners and mitigation status.

## Testing validation

- [ ] Each test has a clearly stated design claim.
- [ ] Each design claim has appropriate evidence.
- [ ] Disconfirming evidence is defined before testing where possible.
- [ ] Behavioral evidence is distinguished from stated preference.
- [ ] Subgroup and access differences are reviewed.
- [ ] Critical issues are documented and assigned.
- [ ] High-risk concepts receive additional safeguards.
- [ ] Prototype evidence is not overclaimed as implementation proof.

## Decision validation

- [ ] Rankings are compared across scenarios.
- [ ] Monte Carlo rank stability is reviewed.
- [ ] Weight sensitivity is reviewed.
- [ ] Threshold failures are reviewed.
- [ ] High review-priority concepts receive additional testing.
- [ ] Advance, revise, pivot, stop, or pilot decisions are documented.
